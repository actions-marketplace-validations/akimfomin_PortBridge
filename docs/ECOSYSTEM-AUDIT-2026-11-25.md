# Проверка новых источников PortBridge · 25 ноября 2026 г.

Проверены 23 адреса из аудита и дополнительные кандидаты из GitHub Topics, истории форков, ссылок между командами и выдачи PortBridge. Все 23 адреса ответили HTTP 200. XValkyrie уже отслеживался. Добавлены 18 адресов из аудита и два дополнительных источника. В реестре теперь 45 репозиториев, включая ветки и инструменты одной команды.

Для каждого адреса сверены публичные метаданные, ревизия основной ветки, файлы лицензии и технически полезное изменение или документ. Указанные ниже изменения и прогоны принадлежат авторам источников. Индексация читает открытые задачи, PR, коммиты основной ветки и результаты CI через существующий механизм. Инвентаризация путей сделана по GitHub tree API. Сборки, изображения, материалы игр и бинарные таблицы не загружались. Ряд производных VIctory указывает, что для BCPack распространяется отдельная таблица вне лицензии репозитория. Метаданные этих проектов дают доступ к их обсуждениям и истории. Для повторного использования кода нужно отдельно сверить лицензию нужного файла. [Заявленная область лицензии](https://github.com/0x0007b/XBVK/blob/858cd6abf750af0616a29a1d3f62c564ef1f408c/docs/asset-policy.md#the-one-exception)

## Что показывают опубликованные измерения

- PastiiJay сообщает, что Lab 39 на RX 9070 XT прошла пролог и первую миссию с ручным сохранением за 77 минут без сбоя. Средняя частота с включёнными загрузками около 5,2 FPS, медиана 4,9, максимум 12,5, рендеринг в 720p с масштабированием FSR. Автор связывает восстановление физики воды с совместным использованием возврата текстур на CPU из vx-layer и схемы XOR-размещения из XTP. Второй прогон, упомянутый автором на RTX 5070 Ti, касается поведения воды. Полный игровой маршрут независимо не проверялся. [Отчёт Lab 39](https://github.com/PastiiJay/klbf-lab-beta/blob/1be1d38a705122001fe7ffb89ba961131c5eb0a9/README.md#L49-L57) · [vx-layer](https://github.com/Geckomacabre/vx-layer/commit/eee5667d7119bc4a378214621e1b18a814ebe80f) · [XTP](https://github.com/MiamiGame/XTP/commit/00c60fb197434c4987156779466a2ab41d5be2df)
- XBVK указывает 8–13 FPS в отдельных сценах. victory-perf указывает около 14 FPS в лёгком коридоре при 50% масштаба рендеринга и 4,5–6,5 в тяжёлых сценах. Scarlight приводит 1,45–1,7 FPS для нескольких сборок базы и 3,0 для отдельной комбинации. Методики, сцены, настройки и версии различаются. [XBVK](https://github.com/0x0007b/XBVK/blob/858cd6abf750af0616a29a1d3f62c564ef1f408c/README.md#current-status--performance) · [victory-perf](https://github.com/vitutu1/victory-perf/blob/ffed22db45d43ba0a24cd8a2d9b3270523791283/README.md#L20-L25) · [Scarlight](https://github.com/pablogonz12/Scarlight/blob/4aad7d3dac2953b97b4395842cc0c899ff0d4d92/README.md#status)
- Автор victory-fork отозвал сравнение 6,0→8,9 FPS из разных сцен. Его последующая оценка сравнивает тренды двух отдельных прогонов при одинаковом числе вызовов отрисовки. Для причинной оценки нужен один и тот же воспроизводимый вход, контроль изображения и повторные прогоны. [Исправление автора](https://github.com/fxceless/victory-fork/commit/0b0074e0b2765e574c622e9a3de566f20f04135b)
- Разбиение больших программ XCL и новая организация временной памяти создают разные эффекты на время компиляции и стоимость отдельных GPU-операций. За исходную работу отвечал Kalmarv. PortBridge предлагает отдельное повторное использование временной памяти, открытое владельцем как черновик #2322. Опубликованный результат ettehn по объёму памяти относится к одной записи. [Слияние базовой работы](https://github.com/xcl-dev/xcl/pull/2126#issuecomment-7164031767) · [Независимая проверка памяти](https://github.com/xcl-dev/xcl/pull/2126#issuecomment-7162128623) · [Черновик PortBridge](https://github.com/xcl-dev/xcl/pull/2322)

## Покрытие и способ воспроизведения

- Публичный вызов `portbridge_ecosystem` до изменения вернул 25 отслеживаемых источников и 122 кандидата, из которых 60 были выданы. В этой выдаче было 14 адресов из аудита, ещё один уже состоял в реестре. Прямой просмотр актуального PortWatch VI подтвердил 16 совпавших адресов. Тема GitHub Xbox Series вывела на Xbox HLE Lab. Атрибуция R4Y вывела на fork Belobug. [Страница источников](https://akimfomin.github.io/PortBridge/#/projects) · [PortWatch VI](https://portwatch-vi.xyz/data/tracker.json) · [GitHub Topics](https://github.com/topics/xbox-series)
- Запрос `python -m portbridge.preflight --q "KLBF Lab RDNA4 Vulkan shader translator" --global --limit 5` нашёл карточку PB-0006 с проверкой PastiiJay для XCL на RDNA4. Глобальный поиск того же вызова выбрал общие термины `vulkan` и `shader` и не вернул KLBF в первых десяти результатах. Для открытия свежих веток использованы точные репозиторные метаданные, а для обнаружения других проектов использованы Topics, история форков и внешние ссылки. [Первичный отчёт из PB-0006](https://github.com/xcl-dev/xcl/pull/1100#issuecomment-7144197194)
- Чтобы повторить проверку, возьмите `git ls-remote https://github.com/OWNER/REPO.git HEAD`, затем сравните `https://api.github.com/repos/OWNER/REPO` и дерево `https://api.github.com/repos/OWNER/REPO/git/trees/SHA?recursive=1` с текстовыми файлами и ссылками перечисленных ревизий. Историю можно сверить по `https://github.com/OWNER/REPO/commits/BRANCH.atom`. Одинаковые хеши коммитов, документы об атрибуции и указанные родительские ветки помогают избежать повторного учёта одной и той же разработки.
- Существующий сбор метаданных охватывает GitHub Issues, PR, коммиты основной ветки и доступный CI. Scarlight также публикует GitHub Discussions. Проверены сама доступность раздела и прямые ссылки. Для произвольных GitHub Discussions и необъединённых веток текущий репозиторный индекс не гарантирует полноту. Покрытие старых записей отражают статусы backfill и incremental после запуска синхронизации. [Покрытие источников](https://akimfomin.github.io/PortBridge/data/health.json)
