# Работа по портированию

В журнале сохраняем первоисточники, точные версии, результат и следующий шаг. Дата первого прогона PortBridge — 24 ноября 2026 года.

## Чтение памяти шейдеров в VIctory

**Проверено локально.** PortBridge связал реализацию VIctory с тестами XCL. Дополнительный источник из Continued показал, почему одинаковые значения при записи из нескольких потоков не защищают тест от гонки. В новый тест для VIctory перенесли приём с записью из одного потока и проверку второй половины регистра. Авторы исходных работ — SAitken91 в VIctory, Vadson159 в XCL и lemma105 в Continued. [VIctory #571](https://github.com/Marvisak/VIctory/pull/571) · [XCL #544](https://github.com/ivall/xcl/pull/544) · [Continued #507](https://github.com/ubiquitarianism/leonida/pull/507)

| Что проверили | Результат |
| --- | --- |
| Версия VIctory `d27cb78960ed495fccb85e0ef1aa497f2cc57c1f` с двумя добавленными тестами | Оба теста прошли на RTX 4070 Ti SUPER и WARP. Windows 11, сборка 28000, драйвер NVIDIA 617.14. |
| Чтение байта с сохранением младшей половины регистра | Восемь случаев на каждом стенде. Проверены четыре позиции байта и два способа расширения значения. |
| Чтение двух байтов на границе соседних 32-битных слов | Один случай на каждом стенде. Из слов `0xAB123456` и `0xDEADCDBE` при смещении 3 получено значение `0xBEAB1357` с сохранением нижней половины регистра. |
| Контроль с прежним переводчиком `d2a4bae1f49533ef5cb512fd1b1ba1513f2e1989` | Оба новых теста выявили прежний отказ на чтении байта или половины слова. |

Проверка охватывает синтетические шейдеры, переведённые в DXIL и исполненные на указанных стендах. Общий запуск тестов модуля вернул 71 зелёный тест, из них пять пропустили внутреннюю проверку из-за отсутствия дополнительных компиляторов или валидатора. Следующий шаг — предложить тесты сопровождающему VIctory #571 и попросить сверить случаи, которые полезно держать общими с XCL.

## Перестановка потоков в Wave64

**Проверены первоисточники.** В XCL #772 два участника опубликовали измерения исходной инструкции `ds_bpermute_b32` на RDNA2. Они подтвердили чтение в пределах своей половины волны. VIctory #439 уже описывает соответствующее поведение. Существующая работа XCL #925 касается в том числе отдельной операции `ds_permute_b32`. [Тест RX 6800M](https://github.com/ivall/xcl/issues/772#issuecomment-7123462950) · [Тест RDNA2 iGPU с масками и смещениями](https://github.com/ivall/xcl/issues/772#issuecomment-7127381205) · [VIctory #439](https://github.com/Marvisak/VIctory/pull/439) · [XCL #925](https://github.com/ivall/xcl/pull/925)

Следующий шаг — сверить текущие изменения XCL с опубликованными контрольными случаями и предложить проверку на Windows только для оставшегося пробела. Обе операции и два разных пути исполнения отслеживаются отдельно.

## Как учитываем пользу

В первом разборе переиспользованы два источника из разных команд и добавлены два проверяемых теста в локальную копию VIctory. Применение сопровождающими и экономию времени будем записывать по ответам или принятым правкам.
