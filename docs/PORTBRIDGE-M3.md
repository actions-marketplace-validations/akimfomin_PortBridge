# M3 · Radar и распределённая Lab

В M3 Radar ведёт устойчивую очередь сравнений версий, из кандидатов высокой уверенности формирует черновики Lab и сохраняет историю проверок. Публикация предложений в собственном снимке происходит в штатной сборке страницы. Принимающая команда сохраняет решение о применении. ## Как работает цепочка Radar и Lab

1. Штатное обновление сохраняет публичные наблюдения. Radar обрабатывает изменившиеся состояния, версии и технические признаки за ограниченный цикл. В одном запуске до 96 событий и до четырёх сравнений на событие. Повтор с тем же содержимым пропускается. Совпадение SHA и проверенный patch-ID привязаны к полной ревизии.
2. Scope Discovery ограничивает поиски, повторно использует кэш и сохраняет слабые находки как исследовательские. Внешний сетевой поиск включается на явном запуске или в подготовленном workflow. Проверка diff ограничена четырьмя попытками и только закреплёнными публичными коммитами. Используется существующий `git patch-id --stable`. Равенство этого ID описывает нормализованный diff одного коммита. [Git patch-id](https://git-scm.com/docs/git-patch-id)
3. Radar показывает два исходника, версии, связь, уверенность, пользу, риск, специализацию и следующий шаг. Высокая уверенность разрешает создание черновика на точных свежих версиях. Ревьюер отдельно решает, можно ли предлагать черновик добровольцам.
4. Доброволец явно занимает одну проверку. Удержание ограничено сроком и квотой. При истечении, отказе или смене версии проверка освобождается или требует повторной сверки. Повторная независимая проверка выдаётся другому участнику.
5. Структура отчёта сверяется во время приёма. Ревью выполняется уполномоченным участником, отличным от автора отчёта. Подтверждение требует реально проверенного артефакта. Можно подать отрицательный результат, исправить или отозвать отчёт. Разные результаты одинаковой проверки остаются открытыми до разбора.
6. С согласия автора проверенное доказательство доступно в Search. Сводка для принимающего проекта готовится как черновик. Метки `delivered` и `adopted` требуют указанного первоисточника события в принимающем репозитории и явной проверки. Сама система ничего туда не отправляет.

SQLite сохраняет idempotency key, версии кандидата, исполнителя, автора отчёта, роль ревьюера и доказательство решения. Данные видимы по существующим правам Exchange. Публичный снимок не включает токены, частные профили и непроверенные тексты отчётов. Компетенции и запросы не назначают добровольцев автоматически. [SQLite transactions](https://www.sqlite.org/lang_transaction.html) · [Решение M3](decisions/015-radar-and-volunteer-lab.md)

## Оценка высокой уверенности

Для рейтинга заранее заморожены 44 пары с прямыми ссылками и двумя закреплёнными версиями. Разметка оценивает, можно ли составить полезное общее сравнение по конкретному механизму. Это отдельная выборка от двух свежих демонстраций. Её разметил исполнитель до написания нового правила. Внешняя повторная разметка ждёт независимого аудитора.

| Показатель | Результат |
| --- | ---: |
| Размеченных пар | 44 |
| Высокой уверенности | 30 |
| Полезных среди них | 26 |
| Precision высокой уверенности | 86,7% |
| Ложных высокой уверенности | 4 |

Четыре сложных совпадения касаются нормализации и упаковки буфера, поведения NaN при округлении, разных механизмов частичных записей D16 и противоречивых правил NaN. Разметка и выводы сохранены с обеими исходными ссылками. Ни один кандидат высокого ранга не поступает напрямую во внешнюю доставку. ## Реальные сквозные прогоны

**Положительный.** AnyXboxX #354 и victory-fork #1289. Из двух свежих наблюдений Radar создал Lab-черновик без ручного добавления пары. Проверены два публичных diff на `6539f200fa8c96555a2b4f2060caaafad756a88e` и `16a6f8ece4651372bc565fe2c9c88b3415e98ac5`. В обоих есть добавления, связанные с LRU eviction и completed fence. Локальный доброволец подал структурированный отчёт по фактической проверке исходников. Другой тестовый аккаунт выполнил операцию ревью, Search увидел проверенный результат, Lab сформировал черновик сводки. Аппаратное поведение остаётся открытым. [AnyXboxX #354](https://github.com/LooperSalty/AnyXboxX/pull/354) · [victory-fork #1289](https://github.com/fxceless/victory-fork/pull/1289)

**Отрицательный.** AnyXboxX #350 и victory-fork #1286. Автоматический кандидат помог проверить гипотезу об идентичном патче. Два реально прочитанных head diff дали разные стабильные patch-ID. Отчёт FAIL прошёл независимый от автора путь ревью в стенде. Гипотеза получила статус `rejected`, а отрицательная проверка видна в Search. В обоих проектах упоминается MEM_DECOMMIT. Этот общий механизм допускает отдельное сравнение. [AnyXboxX #350](https://github.com/LooperSalty/AnyXboxX/pull/350) · [victory-fork #1286](https://github.com/fxceless/victory-fork/pull/1286)

Оба сценария используют реальные публичные первоисточники и фактически прочитанные diff. Учётные записи для прогона локальные. Подтверждения от сопровождающих команд, GPU-тестов и внешней доставки в этих прогонах нет. Третий подготовленный вариант для добровольца — сверка установленного интерфейса при выключенном и включённом D3D12 SR FrameLab. Ещё один вариант — межплатформенный синтетический тест Wave32, допускается только после уточнения общего наблюдаемого условия. [FrameLab #36](https://github.com/5headsmartbtw/leonida-framelab/pull/36) · [Сравнения PS5](PORTBRIDGE-PS5-SPEC.md)

## Согласованность и восстановление

Сравнены локальный и статический сайты, CLI, HTTP API и MCP по ID кандидатов, закреплённым версиям и состоянию Lab. Search показал проверенный PASS и проверенный FAIL по каноническим ссылкам. Chrome прошёл пять представлений, включая русскую карточку Lab на ширине 390 px. Сборка сайта использует исключающий внешнюю запись проход Radar. Отдельно проверены повтор без дубликатов, восстановление из SQLite checkpoint, очередь при 429, пропуск запроса до конца паузы и повтор поиска по прежней ревизии после восстановления. Отклонённый отчёт не попадает в Search как результат. Противоречивые отчёты помечают проверку как снова открытую.

## Локальный запуск и порядок проверки

```sh
python -m portbridge --db work.sqlite3 radar --refresh --limit 96
python -m portbridge --db work.sqlite3 radar --confidence high
python -m portbridge --db work.sqlite3 lab --kind source-only
python -m portbridge --db work.sqlite3 export --out dist
python -m portbridge --db work.sqlite3 serve --offline
```

Для живого ограниченного поиска добавьте `--discovery` к команде обновления Radar. Для действий Lab нужен локальный Exchange с ключом нужной роли. Просмотр задач, версии, промпт и синтетические инструкции открыты в браузере и MCP. Авторизация и запись отключены по умолчанию. [Локальные действия](PORTBRIDGE-M3-LAB.md)

В M3 сохранены все 122 требования. Независимый аудит M0–M2.1, качество широкой выдачи и публичная эксплуатационная приёмка открыты. Автоматическая доставка не включена. Шесть обращений актуализированы в отдельном локальном файле. Старые версии сохранены. Переход к M4 ждёт решения владельца.
