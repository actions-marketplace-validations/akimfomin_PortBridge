# M2.1 · контроль рекомендаций и самостоятельный поиск

Локальный кандидат продолжает M2 и сохраняет все 122 требования. Широкая выдача остаётся доступной. Техническая рекомендация требует заранее проверенной связи конкретной проблемы с первоисточником и подходящим тестом. Находки ограниченного сетевого поиска остаются отдельными исследовательскими ссылками.

## Пять ложных совпадений M2

Пять пар повторились на исходном неизменённом наборе. Совпадение в поиске и право предложить техническую проверку теперь учитываются отдельно.

| Запрос и найденный источник | Причина и риск | Влияние и исправление |
| --- | --- | --- |
| `stack-lifetimes` → Mesa ACO spill slots | Общая тема повторного использования scratch. ACO распределяет слоты внутри компиляции шейдера. Исходная задача XCL касается времени жизни между dispatch. **Высокий** риск перенести неверное предположение о пересечении. | В M2 по XCL #2322 Mesa появлялась рядом с LLVM среди предложений Action. Без известной технической задачи она не получает право на рекомендацию, проверку или перенос. |

Прежние широкие результаты сохранены, в том числе пять размеченных ложных попаданий. Все пять исключены из технической выдачи. Источник с совпавшим URL или точным SHA тоже остаётся находкой, если применимость к принимающей задаче ещё не разобрана. [Регрессионная проверка](../tests/test_discovery_incremental.py)

## Пять уровней доказательств

| Уровень | Что означает |
| --- | --- |
| `source_found` · найденный источник | Есть ссылка. Сеть, текстовое сходство, точный символ или высокий ранг дают материал для чтения. Сохранённые ссылки показывают дату чтения. |
| `potentially_applicable` · потенциально применимо | Есть рассмотренная связь с конкретным открытым Issue или PR, закреплённая ревизия, лицензия, границы и тест. Из прежних разобранных совпадений допускается основное, если оно прошло это условие. |
| `technically_verified` · технически проверенное соответствие | Проверяющий подтверждает один механизм в обеих реализациях на указанных ревизиях и с условиями сравнения. |
| `reproducible_fix` · воспроизводимое исправление | Изменение в принимающем проекте подтверждено контрольным прогоном, включая воспроизводимый вход и сопоставление с исходным поведением. |
| `adopted_by_team` · принятие другой командой | Есть подтверждение принимающей команды, например решение, merge или связанный запуск, в котором она использовала результат. |

Автоматический сбор выдаёт только первый уровень. M2.1 выдаёт второй уровень для уже разобранной основной связи. Остальные уровни требуют отдельных доказательств и здесь остаются открытыми. `evidence_stages` перечисляет все пять уровней в JSON. Поле `radar_candidates` теперь содержит только такие прежние разобранные связи как предложения к проверке. Оно не записывает в Radar, Lab или Impact.

## Сопоставимое сравнение SEARCH-07 и SEARCH-08

Новые 54 проверки закреплены в коммите `30528ce` до изменения кода. Набор включает 14 целевых публичных задач, 12 отрицательных запросов и 28 точных URL. Исходные публичные заголовки собраны до замера из шести репозиториев. Набор не менялся по результатам. Для сравнения берётся один и тот же текст, тип результата Issue/PR и глубина пять. GitHub ищет заголовки в шести репозиториях. PortBridge всех трёх версий получает один замороженный снимок из 184 открытых записей тех же репозиториев. GitHub видит также историю за пределами снимка. Из 15 результатов GitHub один более старый PR находится за пределами снимка. Он был лишним результатом. Все 14 целевых записей присутствуют в обоих режимах. В каждой положительной паре размечена одна целевая запись, поэтому предел Precision@5 в этом замере равен 20%. Лишние совпадения считаются отдельно. У положительных запросов другая запись может оказаться полезной, хотя она и не отвечает на заданную проверку. На отрицательном наборе выдача считается ложным сигналом. На общей части снимка GitHub вернул те же 14 целевых результатов и ни одного дополнительного. Все результаты и ответы на точные URL сохранены. Точный URL GitHub проверен отдельным чтением REST API. Для старых ссылок XCL и victory-fork учтены подтверждённые переименования. Отдельный прогон исходного набора сохранил 39/39 по PB-ID и ссылкам на отчёты. В GitHub нет идентификаторов PB-ID, поэтому они не входят в трёхстороннюю таблицу.

Индекс общих публичных наблюдений на этом снимке занимает 669 712 байт во всех трёх версиях. Встроенный Discovery добавляет 77 216 байт в M2 и 77 369 байт в M2.1. Снимок M2.1 с результатами пилота занимает 99 703 байта. Создание и заполнение локальной базы заняло около 56 мс. Сборка общего индекса заняла около 22–25 мс. Это работа на одном компьютере без нового сетевого сбора. Внутренний размер и стоимость обновления индекса GitHub недоступны. Для сравнения измерены 26 сетевых запросов поиска и 28 точных чтений. Локально измерена задержка от вызова preflight без запуска процесса. У GitHub измерено время HTTP с сетью. Это разные условия задержки, числа приведены с указанием границ.

На прежней тематической выборке широкая выдача Discovery удержала 97,5% Recall@5 и пять явно отрицательных совпадений. Фильтр рекомендации убрал эти пять из технического пути. Новый внешний поиск дал ссылки для девяти из десяти новых задач. По основному поиску Issue/PR GitHub дал меньше лишних результатов. SEARCH-07 воспроизводим. По SEARCH-08 улучшение ограничено внешним покрытием и безопасностью рекомендаций. Общая приёмка и независимая оценка технических рекомендаций остаются открытыми.

## Режимы и проверка интерфейсов

Из каталога можно выполнить ограниченный сбор отдельной командой. Опция `--discovery` добавляет тот же сбор после обычного инкрементального импорта. Если предыдущий проход достиг лимита, следующий проход может продолжить с ещё не просмотренных свежих записей.

```sh
python -m portbridge.discovery_scan --db local.sqlite3 --online
python -m portbridge --db local.sqlite3 incremental --discovery
python -m portbridge.discovery_search --db local.sqlite3 --url https://github.com/xcl-dev/xcl/pull/2697
```

Один пакет рассматривает до 64 наблюдений, до пяти логических поисков по первой странице, до пяти ссылок на запрос и расходует до 14 с бюджета запуска поиска. На один логический запрос возможна одна повторная попытка сетевого клиента. Разрешены 15 публичных внешних репозиториев и анонимные запросы. Тела issues и произвольные приватные строки не сохраняются. Нормализованный запрос делит кэш между задачами. Успех кэшируется на сутки, сетевой сбой сохраняет старый результат как устаревший и откладывает повтор. Один процесс выполняет поиск по каталогу одновременно. Штатное обновление без отдельной опции не запускает внешний поиск. [Лимиты GitHub](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) · [Код поиска](../portbridge/discovery_scan.py)

Браузер на местной и статической версии, CLI, локальный API, MCP stdio и сводка Action по общему снимку сверены по XCL #2322 и #2697. Для #2322 проверена единственная техническая рекомендация LLVM. Для #2697 проверены исследовательские ссылки и отсутствие технической рекомендации. Тесты воспроизводят недоступность источника, ограничения API, чтение сохранённой ссылки и возврат к встроенной подборке при недоступности публичного снимка. Прогон Action использовал локальный HTTP-снимок. Публичный прогон нового кандидата остаётся открытым. Чистая копия прошла 216 тестов. По 82 запросам браузер и Python совпали по источникам и уровню доказательств.

Независимый аудит M0–M1 и публичная эксплуатационная приёмка M1 открыты. Владелец предварительно оценил M2 положительно. Следующая точка решения — независимая проверка и приёмка M2.1. [Реестр](PORTBRIDGE-CHECKLIST.md)
