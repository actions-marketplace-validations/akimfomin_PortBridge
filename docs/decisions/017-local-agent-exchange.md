# M5 agent exchange and subscriptions

PortBridge uses MCP stdio for tools and the existing scoped loopback Exchange for voluntary work. Public consumers pull one versioned JSON snapshot. They can keep a local cursor and schedule it themselves. With no network or a stale snapshot the cursor remains usable, and a disappearance is reported as a feed change. Revoked or superseded work stops appearing in the next eligible feed.

We compared MCP stdio and Streamable HTTP, A2A tasks and discovery, and the A2A Python SDK. MCP is already supported by the target editors. A2A defines agent discovery, remote task state and notifications, which would require ownership, exposure, authentication and operations that this pilot has yet to justify. Two protocol clients completed the experiment through the existing service using their own credentials. The repository already offers a fixed-purpose read-only Actions job. A local scheduler around the digest is sufficient for opt-in monitoring. No paid dependency or central model inference is required. [MCP transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) · [A2A specification](https://a2a-protocol.org/latest/specification/) · [A2A Python implementation](https://github.com/a2aproject/a2a-python) · [GitHub Actions triggers](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)

Resolved reports and Radar suggestions remain different data states. The preflight and partner tools read the same projections as the site and API. Exchange mutation needs an explicit opt-in server flag and a scoped key. An independent review decision and the original report URL are both retained. A future remote service or Agent Card requires a separate security and operational decision.
