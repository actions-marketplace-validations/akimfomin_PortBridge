## Как повторить

Один раз склонируйте ветку, затем выполняйте команды из корня репозитория с установленным Python. Для следующих итераций достаточно `git pull --ff-only`. Для повтора именно этой версии используйте SHA из ссылки на отчёт.

```sh
git clone --branch audit/review --single-branch https://github.com/akimfomin/PortBridge.git
cd PortBridge
git rev-parse HEAD
python -B -m unittest discover -s tests -v
python -B -m portbridge --db .portbridge/check.sqlite3 export --out .portbridge/check-site --repository akimfomin/PortBridge
python -B -m portbridge.release_gate .portbridge/check-site
python -B -m unittest discover -s tests -p test_release_gate.py -v
python -B audit/replay_discovery.py
python -B audit/agent_pilot.py .portbridge/m51-pilot-replay
```

Для первого экспорта используйте свежую базу, для каждого повтора пилота — новый каталог. Повтор фиксированного поиска работает офлайн. Для сверки с меняющимися публичными источниками доступны `python -B audit/replay_discovery.py --online`, `python -B audit/verify_pilot_sources.py` и [проверка JSON и MCP из одной базы](evidence/lab.md).

## Что остаётся открытым

SEARCH-08 остаётся открытым. На новом примере поиск не нашёл доказательства, пригодного для инженерного решения автора. Linux проверен подстановкой ОС, отдельный физический прогон пилота на Linux не проводился. Проверка экспорта выявляет случайное повреждение файлов по контрольным суммам. Старые экспорты требуется пересобрать для получения нового перечня файлов.

Дальнейшие аудиты передаются обычными коммитами в `audit/review` с обновлением этого файла и проверкой публикуемой истории. Публичный пакет содержит исходники, тесты и очищенные результаты. Рабочие базы, переписка, списки контактов и исходные журналы локальной машины в пакет не входят. Изменения в `main`, Pages, релизы и обращения к командам согласуются отдельно.
