# PortBridge M5.3 — может ли одна ссылка на PR помочь принять решение?

**На пяти свежих PR результат — 0 из 5 у обеих версий.** M5.2 показала 5 ссылок, экспериментальная версия — 11. Ни один источник в выдаче не дал достаточного основания для заранее сформулированного решения. Настройка Discovery остановлена. Обычный поиск в этой ветке использует проверенный код M5.2. [Исходный коммит df8cfd879c17df04644127c35330ef07407e9392](https://github.com/akimfomin/PortBridge/commit/df8cfd879c17df04644127c35330ef07407e9392) · [Исходники испытанного варианта](https://github.com/akimfomin/PortBridge/commit/10182c8c3bb66c25f67e16a6e49fc3d3e38e485a)

## Как проверяли

26 ноября 2026 года до просмотра выдачи в Git зафиксировали правило отбора, пять свежих открытых PR из пяти проектов и вопрос к каждому. Брали первый подходящий PR в списке по времени создания. У Kyty пропустили уже проверенный PR. Для каждой версии разработчик передавал только URL. Обе получили одинаковые полные описания, заголовки и ревизии. Для совпадающего запроса использовали одну и ту же страницу ответа GitHub. На один PR допускались отдельное чтение метаданных и до одного поискового запроса с пятью результатами. Независимый проверяющий увидел ответы экспериментальной версии после фиксации её кода. ### Одно испытанное изменение

Два прежних случая показали, как при выборе широкой темы или отдельного флага теряется контекст реализации. Проверили доступную по тому же бюджету альтернативу. Если в описании повторяется подходящий идентификатор кода, экспериментальная версия ищет его в ранее принятых PR самого проекта. Для распознанных общих операций API сохраняется внешний поиск. В поиске по истории проекта учитываются только изменения, слитые до открытия исходного PR. [Реализация и тесты](https://github.com/akimfomin/PortBridge/commit/10182c8c3bb66c25f67e16a6e49fc3d3e38e485a)

На **известном** Continued #2392 этот вариант самостоятельно нашёл два ранее не названных источника среди первых пяти. В #1891 видно, какие настройки устройства сверить. В #821 есть тест попадания в кэш с положительным контролем на том же драйвере. Итог на трёх известных случаях — 1 решаемый вопрос из 3, у M5.2 было 0 из 3. Эта выборка использовалась при разработке. [Сверка настроек](https://github.com/ubiquitarianism/leonida/blob/1bf5eeafd7041db163a6f027ba6145262f70e48a/runtime/test/vk_pipeline_check.cpp#L1147-L1151) · [Тест с контролем](https://github.com/ubiquitarianism/leonida/blob/32a5d9698022711bc52e3c5cf28766691518dc8e/runtime/test/pipeline_cache_seed_test.cpp#L363-L417) · [Все результаты на прежних случаях](evidence/m53/development-search.md)

Пять свежих PR — небольшая выборка из знакомых проектов. Источники, найденные вручную, помогли сформулировать проверки. Выполнение этих проверок в принимающих проектах, принятие решения авторами и экономия их времени остаются неизвестными. Требование SEARCH-08 остаётся открытым.

**Куда направить следующую итерацию.** Выбрать один вопрос, для которого уже есть эталон, и дать разработчику воспроизводимую проверку. Для Continued #2399 это короткий открытый пример с нулевым VIEW_INSTANCING и известным следующим элементом. Можно измерить смещение и прочитанный тип как у реализации проекта, так и у парсера Microsoft. Здесь заранее известны эталон и наблюдаемый результат, а обе версии поиска вернули пустую страницу. [Парсер Microsoft](https://github.com/microsoft/DirectX-Headers/blob/48a762973271c5a75869946bf1fdbc489a628a5c/include/directx/d3dx12_pipeline_state_stream.h#L1482-L1485)

## Воспроизведение

Обычная версия прошла **262 теста**, экспериментальная — **266**. Ошибок и пропусков — 0 в обеих. Полный экспорт из новой базы и проверка целостности прошли для обеих версий, по 281 файлу в реестре. Для пяти свежих PR обе выдачи совпали целиком при повторе офлайн и при повторном чтении полных описаний через публичный GitHub. [Результаты проверок и соответствие ревизий](evidence/m53/validation.json) · [Инструкция по способам повтора](evidence/m53/replay.md)

```sh
git clone --single-branch --branch audit/review https://github.com/akimfomin/PortBridge.git
cd PortBridge
git worktree add --detach ../m53-baseline df8cfd879c17df04644127c35330ef07407e9392
git worktree add --detach ../m53-candidate 10182c8c3bb66c25f67e16a6e49fc3d3e38e485a
python -B audit/m53_replay.py --arm baseline --code ../m53-baseline
python -B audit/m53_replay.py --arm candidate --code ../m53-candidate
python -B audit/m53_replay_development.py --code ../m53-candidate
python -B -m unittest discover -s tests -v
python -B -m portbridge --db .portbridge/m53.sqlite3 export --out .portbridge/m53-site --repository akimfomin/PortBridge
python -B -m portbridge.release_gate .portbridge/m53-site
```

Для проверки обычного входа по ссылке добавьте `--public-inputs` к двум командам повтора. Они проверяют ревизию, заголовок и хеш полного публичного описания до запуска поиска. Изменение исходного PR или исчерпание квоты GitHub прерывает этот режим. Офлайн-повтор использует сохранённые наблюдения и проверяет весь результат. Тесты, экспорт и проверку целостности экспериментального кода можно повторить теми же тремя командами из каталога `../m53-candidate`.
