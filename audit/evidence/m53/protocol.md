# M5.3 prospective Discovery comparison

Before viewing the listings or running Discovery, take one open, non-draft PR per repository from the five origin repositories already used for the M5.1 and M5.2 prospective tests (XCL, Continued, KytyPS5, AnyPS5 and AnyXboxX). Use the public pulls endpoint sorted by creation descending, first 20, independently per repository. Take the first eligible row whose PR URL is absent from prior audit inputs, other audit evidence and checked-in discovery benchmark fixtures. Skip only cases needing protected game assets, executable downloads, private evidence, or disclosure of private material to evaluate. Documentation and nontechnical changes stay eligible. Never replace a selected case because of the type of potential findings, search availability or output. If a listing is inaccessible report that gap. Freeze the canonical URL, public revision, selection position, title, body hash and public normalization fields. Record a specific falsifiable technical decision from each selected PR before running either engine.

Run the baseline and frozen candidate through ordinary search_link with the PR URL as the sole user input. Each arm gets an empty temporary catalog, the same shipped seed for its release and the same full public PR input bytes. Record a shared bounded first-page response per distinct external query and preserve order, failures and truncation. Compare evidence actually displayed in the first five. Distinguish source verified from a hint already in the PR, new independently applicable technical evidence, unverified pointers, and noise. A novel finding requires a documented implementable decision or concrete check and a source that supports it. Deduplicate per origin and separate PR-level and rank-level counts. For every novel miss run a separate manual search from the fixed decision, report the actual queries, inspected evidence and scope without adding these manual answers to the product. No recruitment, team contact or presumption of adoption.
