# Independent manual search for the five decisions

The reviewer searched the open web from the frozen decisions independently of both versions' ranked suggestions. The initial queries below were sent on 26 November 2026. Follow-up reads checked primary sources. This method can use API documentation, source code and manual query reformulation beyond the product's one GitHub issues page.

| Origin | Actual manual query | Evidence and concrete check |
| --- | --- | --- |
| XCL #2860 | `shader pipeline cache save recorded PSO user cache shader platform file name Unreal Engine FPipelineFileCache GameUserDir ShaderFormat worker platform file` | Epic records used pipeline states by shader platform and documents separate files for scalability levels. It explains which entries are logged after an active file switch. Record one unique PSO per X/S profile in the same directory, restart the other profile, and check that its preloader sees only its entry. The example supports this test design. The XCL worker still needs its own test. [Epic runtime cache documentation](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/RenderCore/FShaderPipelineCache?application_version=5.8) |
| Continued #2399 | `D3D12 pipeline state stream view instancing D3DX12ParsePipelineStream alignas void CD3DX12_PIPELINE_STATE_STREAM_VIEW_INSTANCING DirectX-Headers` | Microsoft's parser advances over the stream element by the size of the typed view-instancing subobject. Its template is pointer-aligned. Build a zero-count descriptor and a following known element, then compare its actual offset with the Microsoft element size. Microsoft's parser passes the descriptor to a callback, so arbitrary callback behavior falls outside that structural comparison. [Element parser](https://github.com/microsoft/DirectX-Headers/blob/61c7718954ec73dbdd43c723240fe1a0452a3724/include/directx/d3dx12_pipeline_state_stream.h#L1905-L1908) / [alignment](https://github.com/microsoft/DirectX-Headers/blob/61c7718954ec73dbdd43c723240fe1a0452a3724/include/directx/d3dx12_pipeline_state_stream.h#L33) |
| KytyPS5 #2551 | `Vulkan vkDestroyImage all submitted commands refer to image execution complete VkImage Vulkan specification` | Vulkan rule VUID-vkDestroyImage-image-01000 requires completion of all submitted uses, including through image views. Hold a submitted use pending, force pressure, and check backing destruction only after the last use completes before retrying the allocation. This establishes the Vulkan condition; it does not establish coverage by a particular scheduler's wait or guarantee eventual allocation success. [Khronos rule](https://docs.vulkan.org/refpages/latest/refpages/source/vkDestroyImage.html#VUID-vkDestroyImage-image-01000) |
| AnyPS5 #27618 | `POSIX errno may be changed on successful call save errno around logging mmap ENOMEM The Open Group errno` | The Open Group web endpoint was unavailable to this reader. Linux's errno manual confirms that even a successful call can overwrite errno, and its example saves errno before a diagnostic print. Make the diagnostic change errno and assert MAP_FAILED plus ENOMEM on return. This establishes a host-wrapper check. The guest exception number is outside the Linux contract. [errno(3)](https://man7.org/linux/man-pages/man3/errno.3.html) / [mmap(2)](https://man7.org/linux/man-pages/man2/mmap.2.html) |
| AnyXboxX #448 | `LLVM LangRef fcmp false true no comparison always true NaN DXIL supported floating point compare predicates Microsoft DirectXShaderCompiler` | LLVM 17 defines these two results independently of the operands. Compare constant-lowered and reference outputs over finite, infinite and NaN inputs. This supports the value-semantic half of the decision. The reviewed DXIL documentation did not independently settle validator acceptance. [LLVM fcmp semantics](https://releases.llvm.org/17.0.1/docs/LangRef.html#fcmp-instruction) / [DXIL reference inspected](https://github.com/microsoft/DirectXShaderCompiler/blob/2600ae89a6153302421b13b4db7d3bd1bd0d9385/docs/DXIL.rst) |

These five manual checks are review hypotheses grounded in outside sources. None of the proposed project or hardware checks was run. None is an inferred project defect, a delivered fix or an external adoption event.

## Separate manual search within each origin repository

To distinguish an outside answer from a missed earlier PR, the reviewer also searched each receiver's already-merged PRs with one manually chosen identifier taken from the origin. Each query used its PR creation timestamp, GitHub's default relevance order and the first five rows. The fields and rank order below are linked separately from product search receipts. [Exact queries, counts and ranked URLs](manual-receiver.json)

- XCL `used-only` returned ten candidates. The first five included the original usage-list reader and the precompile-worker implementation. They establish the shared filename and worker boundary, but do not themselves implement or test profile separation. [Used-pipeline reader](https://github.com/xcl-dev/xcl/pull/1982) / [preparation workers](https://github.com/xcl-dev/xcl/pull/2624)
- Continued `CreateDerivedPipelineState`, KytyPS5 `WaitPriorityOperations`, and AnyXboxX `fcmp` each returned a complete empty page under this scope.
- AnyPS5 `MAP_NO_OVERWRITE` returned two PRs. The first explains why an overlapping mapping returns ENOMEM and shows the existing mapping survives. This supplies a setup/control, not the post-diagnostic errno guarantee in the fixed question. [Prior mapping fix](https://github.com/boykopovar/AnyPS5/pull/994)

The manually chosen searches occurred after recording the baseline and did not modify the product, its queries, the five origin inputs or the fixed grading threshold.

A second reader also identified the [typed stream walker in DirectX-Headers v1.614.1](https://github.com/microsoft/DirectX-Headers/blob/48a762973271c5a75869946bf1fdbc489a628a5c/include/directx/d3dx12_pipeline_state_stream.h#L1482-L1485) and [the pinned Vulkan image-lifetime rule](https://github.com/KhronosGroup/Vulkan-Docs/blob/043260d06e96c8586492be41cc109945e92a69ff/chapters/resources.adoc#L4137-L4139).
