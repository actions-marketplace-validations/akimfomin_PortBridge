# NET-12 · повторное использование PortBridge

Команда читает сохранённые публичные подтверждения и работает офлайн. Полный локальный план `python -m portbridge.network --db <путь-к-базе>` возвращает тот же объект `outcome`. Для передачи аудитору достаточно короткой команды.

```sh
python -B -m portbridge.network --outcomes-only
python -B -m unittest discover -s tests -p test_network_usage.py -v
```

| Поле в JSON | Хотя бы одно применение | Повтор на разных задачах в разные дни UTC | Цель |
| --- | ---: | ---: | ---: |
| `outcome.historical` | 3 проекта | 1, FrameLab | 3 |
| `outcome.relaunch` | 0 независимых команд | 0 | 3 |

В прежнем журнале пять событий. FrameLab применил результат в PR #12 и позднее принял проверку в задаче #15. У AnyXboxX есть одно применение, оба события Continued произошли в один день. В исходных записях сохранены авторы, время и первичные ссылки. ## Как учесть новое подтверждение

1. Откройте публичную запись принимающей команды. Проверьте автора, задачу, дату технического действия и какой именно код PortBridge команда применила. Для `relaunch_usage` сохраните `actor`, `kind` (`technical_trial` или `technical_reuse`), `at` с часовым поясом, `task` и прямую ссылку `proof` на задачу, комментарий, ревью или коммит в принимающем репозитории. В `version_evidence` скопируйте короткую строку источника с полным SHA либо точным названием версии, например «PortBridge M5.1». В `portbridge_revision` укажите соответствующий SHA из реестра версий. Установите `reviewed: true` после сверки. Проверяющий устанавливает смысл публичного текста и независимость участника. CLI проверяет поля, закреплённую версию, время и повторы.
2. В `relaunch_teams` сопоставьте принимающий репозиторий (`owner/repo`) с основным публичным репозиторием независимой команды в том же формате. У одной команды с несколькими репозиториями должен быть один идентификатор. Неоднозначная принадлежность исключает запись из результата. Для локальной проверки передайте `--ledger <путь-к-JSON>` с этими двумя полями. Итоговые публичные факты можно добавить в тот же формат в файле данных.
3. В `relaunch_versions` перечислены публичные ревизии кандидатов M5, M5.1 и M5.2 с временем создания коммита по Git. Подтверждение должно быть датировано не раньше соответствующего коммита. При появлении новой пилотной ревизии добавьте её проверенный SHA и время коммита в публичный файл. Демонстрации на стороне PortBridge, приглашения, размещение ссылки и записи без подтверждения версии оставляют новый счётчик без изменений.

Записи прежнего формата `usage` остаются историческими при любом повторном импорте. Уже учтённая историческая ссылка исключается из результата нового пилота даже при смене даты или метки версии. Для подтверждённого повтора нужны два разных первичных свидетельства на разных задачах и в разные дни UTC. `single_or_repeat_team_count` учитывает команду с первого принятого события. `verified_repeat_team_count` и `reached` относятся к повторному использованию. Тесты с вымышленными событиями проверяют достижимость цели трёх команд. [Регрессионные тесты](../../tests/test_network_usage.py)
