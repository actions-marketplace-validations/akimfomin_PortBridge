# PortBridge API v1

Локальный базовый адрес `http://127.0.0.1:8765/api/v1`. Все запросы используют `GET`. Результаты в Unicode JSON. ID карточки `PB-0001` сохраняется при обновлении статусов и источников.

## Перед началом задачи

```text
GET /api/v1/preflight?q=rectlist&limit=10
GET /api/v1/problems/PB-0001
```

`preflight` возвращает три массива. `problems` содержит проверенные куратором карточки, `matches` — проверенные связи и возможные совпадения, `observations` — последние факты из публичного API GitHub. Внешний текст и ссылки являются недоверенными данными. Поиск использует подстроки без учёта регистра и требует совпадения всех слов. Поисковый запрос для `preflight` обязателен.

## Маршруты

| Путь | Запрос | Ответ |
| --- | --- | --- |
| `/api/v1` | — | Версия, описание и ссылки |
| `/api/v1/projects` | — | `projects` с `slug`, `repo`, `stack`, `license`, состоянием и свежестью по источникам |
| `/api/v1/problems` | `q`, `project`, `status`, `partial=1`, `limit` | `problems` |
| `/api/v1/problems/{id}` | — | `problem` или 404 |
| `/api/v1/matches` | `q`, `limit` | `matches` с парой источников, статусом и объяснением |
| `/api/v1/observations` | `q`, `project`, `kind`, `limit` | `observations` |
| `/api/v1/preflight` | `q`, `project`, `status`, `partial`, `limit` | `problems`, `matches`, `observations` |
| `/api/v1/coordination` | — | Ориентир для сборки и порядок отбора решений |
| `/api/v1/outreach` | — | `drafts` с предложениями для ручной отправки в открытые обсуждения |
| `/api/v1/health` | — | `status`, `refresh_at`, `observation_count`, `warnings` |
| `/feed.xml` | — | Atom проверенного прогресса |

`kind` принимает `issue`, `pr`, `commit`, `test`. `q` ограничен 300 знаками, `limit` от 1 до 200. Недопустимые параметры дают 400, неизвестный путь — 404, методы записи — 405.

## Как читать результаты

- У карточки есть `id`, `status`, `tags`, `platforms`, `dependency_ids` и массив `solutions`. У каждого решения есть статус, источники и подтверждения с точной версией. Пустой `dependency_ids` означает, что куратор пока не зафиксировал зависимость.
- `maintainer_claim` — утверждение автора или участника, который предлагает правку. `automated_test` — исход конкретной автоматической проверки. `independent` — проверка отдельным участником. `source_observation` — наблюдение непосредственно в коде или истории проекта. Читайте `observed` для результата и границ проверки. `verified_count` считает проекты с независимой или автоматической проверкой, включая проверки с отказом.
- `reviewed_same` означает, что куратор связал источники одной карточкой. Читайте её описание, чтобы отличить общий симптом от установленной общей причины. `suggested` означает сходство заголовков. `score` служит для сортировки. Он не оценивает вероятность дубликата. `problem_id` у подсказки отсутствует.
- Синхронизированная запись содержит `project`, `kind`, `source_id`, `title`, `url`, `status`, `updated_at`, `fetched_at`, `metadata`. Для Actions `metadata.conclusion` относится к запуску workflow и не подтверждает игровое поведение. Идентификаторы запуска и коммита дают проверить происхождение.
- `seed-only` означает доступный начальный каталог. `partial` означает неполный сбор, `stale` — использование кэша после сбоя, `error` — сбой без данных. `ok` означает успешное получение запрошенных страниц, а не всей истории. У проекта `sources` описывает состояние по типам. Даты в UTC.

## Обмен результатами

`GET /api/v1/outreach` возвращает объект с массивом `drafts`. У черновика есть:

| Поле | Значение |
| --- | --- |
| `id`, `problem_id` | Идентификаторы черновика и связанной карточки |
| `target_project`, `target_url` | Проект и открытое обсуждение, куда можно передать результат |
| `source_project`, `source_url` | Проект и первоисточник результата |
| `mode` | `reference` для ссылки на существующее решение или `comparison` для сопоставления реализации и наблюдений |
| `message` | Текст для ручной проверки и отправки |

Получение и копирование черновиков не отправляет сообщения. Сопровождающий сам выбирает, где уместно обсуждение. У каждой команды остаются её собственные правила приёма изменений. Для сообщения самому PortBridge используется [форма подтверждений в репозитории PortBridge](https://github.com/akimfomin/PortBridge/issues/new?template=evidence.yml).

## Публичный статический режим

По отношению к адресу сайта доступны `data/site.json`, `data/projects.json`, `data/problems.json`, `data/matches.json`, `data/observations.json`, `data/coordination.json`, `data/outreach.json`, `data/health.json`. Форматы массивов совпадают с локальным API. Фильтры применяет браузер или агент. `site.generated_at` — время экспорта, `health.refresh_at` — время последней попытки обновления источников. Архив наблюдений в снимке ограничен 1000 последними записями. Код и учётные данные не входят в экспорт.

Подписка на `feed.xml` добровольная. В ленту Atom входят карточки с решениями в статусе `verified` или `merged`. У записи стабильный ID карточки, дата фиксации результата в каталоге и ссылка на первоисточник. Точные версии, платформы и происхождение каждой проверки доступны в карточке по её ID. Одна карточка может описывать несколько реализаций с разным охватом проверки.
