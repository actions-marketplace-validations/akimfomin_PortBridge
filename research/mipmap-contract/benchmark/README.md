# Vulkan mipmap replay

The replay measures the full GPU mip generation chain of a pinned open shader. Blender currently issues at most two mip levels per dispatch and inserts a memory barrier between dispatches. NVIDIA's independent implementation reports 112.000 µs for its scheduler, 159.744 µs for per-level blits, and 159.232 µs for per-level compute on 4096×4096 sRGBA8 on an RTX 3090. The replay tests the NVIDIA scheduling variants independently of Blender. Neither the upstream numbers nor the results below measure Blender scene performance. [Blender's current host scheduler](https://github.com/blender/blender/blob/82f4325bf96ddf50b449cee63518d184eafbb469/source/blender/gpu/intern/gpu_texture_mipmap.cc#L139-L147) · [NVIDIA upstream timings](https://github.com/nvpro-samples/vk_compute_mipmaps/blob/6c248f554e91329875e9860f2258019a32b44ee9/README.md#parallelization-strategy)

## Results

RTX 4070 Ti SUPER, driver 617.14, Windows build 28000.3501. Shaders use the original NVIDIA sRGBA8 interface and scheduler at `6c248f554e91329875e9860f2258019a32b44ee9`. “Automatic” selects NVIDIA's existing fast path where applicable and falls back to its general path elsewhere. The standalone runner generated opaque xorshift RGB or a constant opaque color. The benchmark timestamps enclose mip generation, including inter-dispatch synchronization. Host work, pipeline creation, upload and readback are outside that interval.

| Shape and input | Comparison | Medians (µs) | Median paired change (µs) | Unequal generated bytes |
| --- | --- | ---: | ---: | ---: |
| 4096×4096 hashed | NVIDIA general → automatic | 164.864 → 151.552 | −18.432 | 3,539,592 / 22,369,620 |
| 2048×2048 hashed | NVIDIA general → automatic | 30.720 → 15.360 | −16.384 | 883,889 / 5,592,404 |
| 257×193 hashed | NVIDIA general → automatic | 9.216 → 6.144 | −2.048 | 86 / 65,532 |
| 4096×4096 hashed | NVIDIA automatic → PortBridge, fixed full Wave32 | 148.640 → 160.768 | +2.048 | 0 / 22,369,620 |
| 2048×2048 hashed | NVIDIA automatic → PortBridge, fixed full Wave32 | 14.336 → 16.384 | +2.048 | 0 / 5,592,404 |
| 256×256 hashed | NVIDIA automatic → PortBridge, fixed full Wave32 | 4.096 → 3.072 | −1.024 | 0 / 87,380 |
| 257×193 hashed and constant | NVIDIA automatic → PortBridge, fixed full Wave32 | 6.144 → 6.144 | 0 | 0 / 131,064 |

The existing general and automatic schedules produced different bytes on hashed textures, by up to two channel values. The two schedules matched the exact known output for constant opaque controls. Under the matched full-Wave32 contract, the PortBridge lane-index change matched all **28,180,468** generated bytes across the five cases. The performance data show no consistent improvement over the strong fast baseline. In an earlier exploratory run with compute-stage timestamps, the 4K paired change was −2.048 µs. In the final run background GPU activity snapshots were 48–51% and there were long individual timing outliers. Timing uses single-command-buffer alternating AB/BA pairs. The paired median summarizes per-pair differences and can differ from the difference of separately computed medians.

The independent NumPy oracle uses a separable area filter and standard sRGB transfer functions. Odd axes give each output pixel an equal-size interval in source space. The oracle evaluates both rounding at each intermediate mip and carrying linear values between levels. In the smaller hashed cases, the maximum absolute observed channel difference from either reference was two for square 256 and one for non-power-of-two 257×193. Both references matched constant controls exactly. GPU tests covered one device and one format, with opaque input. Validation layers, hardware Wave64, Blender runtime integration, layered formats and partial updates were outside this run. ## Reproduce

Get the Apache-2.0 NVIDIA sources and a C++20 toolchain, Vulkan headers and loader, `glslang`, `spirv-val`, and Python with NumPy. The package refers to external source at its pin. NVIDIA sources, binaries and large generated images are not included. [NVIDIA source and license](https://github.com/nvpro-samples/vk_compute_mipmaps/tree/6c248f554e91329875e9860f2258019a32b44ee9/nvpro_pyramid)

From this benchmark directory, for a Windows LLVM-MinGW build with those tools on PATH:

```powershell
$Nvpro = 'C:/work/vk_compute_mipmaps'
$VkHeaders = 'C:/work/Vulkan-Headers/include'
$Scratch = 'C:/work/mipmap-replay'
git clone --filter=blob:none --sparse https://github.com/nvpro-samples/vk_compute_mipmaps.git $Nvpro
git -C $Nvpro checkout 6c248f554e91329875e9860f2258019a32b44ee9
git -C $Nvpro sparse-checkout set nvpro_pyramid
$Stock = Join-Path $Scratch 'stock'
$Rewrite = Join-Path $Scratch 'rewrite'
New-Item -ItemType Directory -Force -Path $Stock,$Rewrite | Out-Null
Copy-Item "$Nvpro/nvpro_pyramid/*" -Destination $Rewrite
python ../mipmap_contract.py rewrite "$Nvpro/nvpro_pyramid/nvpro_pyramid.glsl" "$Rewrite/nvpro_pyramid.glsl"
foreach ($Variant in 'fast','general') {
    glslang -V --target-env vulkan1.1 -o "$Stock/$Variant.spv" "$Nvpro/nvpro_pyramid/srgba8_mipmap_${Variant}_pipeline.comp"
    spirv-val --target-env vulkan1.1 "$Stock/$Variant.spv"
}
glslang -V --target-env vulkan1.1 -o "$Rewrite/fast.spv" "$Rewrite/srgba8_mipmap_fast_pipeline.comp"
spirv-val --target-env vulkan1.1 "$Rewrite/fast.spv"
$Exports = rg -I -o '\bvk[A-Z][A-Za-z0-9_]+' headless_mipmap.cpp "$Nvpro/nvpro_pyramid/nvpro_pyramid_dispatch.hpp" |
    Sort-Object -Unique
('LIBRARY vulkan-1.dll','EXPORTS') + $Exports | Set-Content "$Scratch/vulkan-1.def" -Encoding ascii
llvm-dlltool -m i386:x86-64 -d "$Scratch/vulkan-1.def" -l "$Scratch/libvulkan-1.a"
clang++ -std=c++20 -O2 -static "-I$VkHeaders" "-I$Nvpro" headless_mipmap.cpp "$Scratch/libvulkan-1.a" -o "$Scratch/mipmap.exe"
$Results = Join-Path $Scratch 'results'
$Case = Join-Path $Results 'result-4096-4096-hashed'
New-Item -ItemType Directory -Force -Path $Case | Out-Null
& "$Scratch/mipmap.exe" $Stock 4096 4096 '4070 Ti SUPER' hashed 35 $Case |
    Set-Content "$Case/timings.csv" -Encoding ascii
if ($LASTEXITCODE) { throw 'Stock replay failed' }
$Case = Join-Path $Results 'fixed-4096-4096-hashed'
New-Item -ItemType Directory -Force -Path $Case | Out-Null
& "$Scratch/mipmap.exe" $Stock 4096 4096 '4070 Ti SUPER' hashed 35 $Case "$Rewrite/fast.spv" |
    Set-Content "$Case/timings.csv" -Encoding ascii
if ($LASTEXITCODE) { throw 'Full Wave32 replay failed' }
python analyze.py $Results
```

Use `glslangValidator` if that is the installed executable name. On a system with a standard linkable Vulkan loader, the host build is `c++ -std=c++20 -O2 -I "$Nvpro" headless_mipmap.cpp -lvulkan -o mipmap`. The ordinary replay uses Vulkan 1.2 and an explicitly selected Wave32-capable device. Passing the extra SPIR-V argument uses Vulkan 1.3 and requires full fixed Wave32 via the pipeline stage on both variants. The runner writes mip levels in descending resolution without padding and writes the upload level separately. Run the other rows by supplying their dimensions and pattern, with the repetition count from `timing_pairs_microseconds`.
